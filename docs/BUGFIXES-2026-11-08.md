# Cue 1.3.2 — playback UI corrections

## Changes

- Music closes with a 220 ms fade of the entire composition, including the room outside the engine picture. Cover, spectrum, backdrop and audio share the same curve. The former ellipse exposed a rectangular picture boundary and ended on a small fragment of the cover. Video keeps its pixel iris.
- Returning home finishes the native window glide and waits for the stopped engine's child window to disappear before starting the home entrance. During the glide the parent paints black, without rebuilding the home or playback layouts, allocating differently sized home canvases, or resizing the stopped engine on every frame. Revealing a new file synchronizes the hidden video host once before showing it. Opening a file during the return cancels the pending home entrance.
- Portrait menus use the approved control bar's scale, with a width limit and the existing per-panel height fitting. At 980 × 1740 with base scale 2.5, the bar stays at 3.0 and More increases from 2.5 to 3.0 (20%). Landscape and mini-player scale rules are preserved.
- Timeline previews only use the requested cache interval; an unrelated nearby shot is never substituted. A frame changes directly without a dissolve, and carries its own actual timestamp. Navigation sampling and dispatch follow the current [thumbnail policy](THUMBNAILS-2026-11-08.md); the RAM cache remains bounded to 12 MiB / 256 entries. Phone replies also require their requested interval.
- The supplied Windows source called two DeviceTier methods that do not exist in its header. Call sites now use the existing allow_smooth_motion() and ui_frame_interval() policies, enabling a complete Windows build without changing those policies.

## Validation

- Complete portable C++ test suite, translation/embedded-page checks, Windows x64 cross-compilation and installer payload validation.
- Additional regression coverage: a preview's first paint contains only the new shot; timestamp remains attached to its image; clearing a file clears the preview; music close opacity is monotonic and remains black until stop, playing and paused. Existing portrait-panel bounds tests cover 60 combinations; the report's dimensions also check the 20% menu increase.
- The portrait menu was rendered and inspected using the real portable UI renderer.
- The engine DLL is byte-for-byte the one extracted from the supplied 1.3.2 installer. No engine build or shader source change is included.
- Native Windows/DWM playback and perceived animation smoothness were not executed in this Linux environment. These need confirmation on Windows; compilation and portable tests do not prove visual timing on a real GPU.

## Windows verification

1. Play and pause music in each look; close using Esc, back and More. Check the cover, spectrum and background fade together, without a rectangular mask or residual cover fragment.
2. Open and close 2.39:1, 16:9, square and portrait video. The black window should resize continuously and the home enter once at the final size. Repeat while maximized and with reduced motion. Drop another file during the return and confirm playback takes over.
3. Open More, Settings, subtitles and speed in a 980 × 1740 portrait window, then at each interface size. Check readable text, all rows reachable, and no overlap with controls or window buttons.
4. Hover back and forth across a scene cut, stop the pointer, and revisit cached positions. Each image should change once, without overlapping shots or a nearby cache frame being replaced later. Repeat paused, while playing and while scrubbing.

This is a corrected local 1.3.2 build. No release or repository has been published.
